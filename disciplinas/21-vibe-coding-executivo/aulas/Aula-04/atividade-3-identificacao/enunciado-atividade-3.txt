O desafio da EnglishPro
A EnglishPro é uma escola de inglês. Todo mês, uma parte desses alunos cancelam a matrícula. Cada cancelamento é receita perdida e, quase sempre, custa mais conquistar um aluno novo do que manter um que já está na escola.
Hoje, a escola só percebe que perdeu um aluno quando ele já pediu o cancelamento. A diretoria quer inverter essa lógica: descobrir antes quem tem mais chance de sair e agir a tempo, oferecendo um desconto para quem antecipar a rematrícula.
Mas há um cuidado: dar o mesmo desconto para todos sai caro. Um aluno que já ia continuar não precisa de desconto. Por isso, a oferta precisa ser diferente para cada aluno, de acordo com o risco dele. Isso é hiperpersonalização.
Sua missão
1. Usar o Claude/GPT/GPT/Gemini para treinar um modelo de Machine Learning com o histórico de alunos que cancelaram ou não.
2. Usar esse modelo para calcular a probabilidade de churn (0% a 100%) de cada um dos alunos atuais.
3. Levar essa previsão para o app da escola no Lovable: importar o resultado, cadastrar campanhas por faixa de risco e mostrar a oferta certa para cada aluno quando ele fizer login.
1.1 Objetivos de aprendizagem
Ao final do exercício, você será capaz de:
Explicar, em linguagem de negócios, como um modelo de Machine Learning aprende com dados históricos.
Conduzir uma IA Generativa para treinar, avaliar e aplicar um modelo de previsão, sem programar.
Ler criticamente o resultado de um modelo: o que ele acerta, onde erra e quanto custa cada tipo de erro.
Transformar uma previsão em ação, desenhando campanhas de retenção por faixa de risco.
Colocar a hiperpersonalização em funcionamento dentro de um produto digital real.

1.3 Conceitos que você vai usar
Termo
O que significa (sem jargão)
Churn
Cancelamento. "Probabilidade de churn" é a chance de o aluno cancelar.
Feature
Uma característica usada para prever, como presença nas aulas ou parcelas atrasadas. É uma coluna de entrada.
Label (rótulo)
A resposta que o modelo aprende a prever. Aqui, a coluna cancelou_60_dias (1 = cancelou, 0 = não cancelou).
Modelo
Uma "receita" matemática que a IA monta a partir do histórico e que depois aplica a alunos novos.
Treino e teste
A base é dividida em duas partes: uma para o modelo aprender e outra, escondida, para conferir se ele acerta em casos que nunca viu.
AUC
Nota de 0,5 a 1,0 que mede o quanto o modelo separa bem quem sai de quem fica. 0,5 é chute; acima de 0,8 é um bom modelo.
Falso positivo
O modelo diz que o aluno vai sair, mas ele ficaria. Custo: um desconto dado sem necessidade.
Falso negativo
O modelo diz que o aluno vai ficar, mas ele sai. Custo: a receita perdida daquele aluno.
Hiperpersonalização
Oferecer a cada cliente uma experiência ou oferta diferente, com base em dados e previsões sobre ele.
Etapa 1 — Treinar o modelo no Claude/GPT
Nesta etapa, você vai entregar ao Claude/GPT o histórico de 5.400 alunos que estiveram na escola. Para cada um, a base mostra cinco características e se ele cancelou ou não nos 60 dias seguintes. O Claude/GPT vai procurar os padrões que diferenciam quem saiu de quem ficou.
2.1 Antes de começar
Abra o Claude/GPT e inicie uma conversa nova só para este exercício. Use a mesma conversa nas Etapas 1 e 2.
Tenha os dois arquivos salvos no seu computador: EnglishPro_Churn_Treino.xlsx e EnglishPro_Dados_Alunos_Prontos_ML.xlsx.
Por que "rodar código de verdade" importa
Uma IA Generativa pode responder de duas formas: calculando (escreve e executa um programa que treina um modelo real) ou estimando (inventa números plausíveis só com base no texto). A segunda resposta parece correta, mas não é confiável.
Por isso, todos os prompts deste roteiro pedem explicitamente que o Claude/GPT execute o código e mostre os resultados. Se em algum momento ele responder sem calcular, peça de novo.

2.3 Passo 2: treinar e avaliar o modelo
PROMPT 2 — Treinar o modelo
Agora treine um modelo de Machine Learning para prever a coluna cancelou_60_dias usando as 5 features. Crie o modelo de treinamento no próprio chat da ferramenta que estamos usando. O modelo é um exercício escolar, não precisar gerar o código em python.
Regras:
- Não use id_aluno nem cancelou_60_dias como entrada do modelo.
- Separe 25% dos dados para teste, que o modelo não pode ver durante o treino.
- Teste pelo menos dois tipos de modelo (por exemplo, regressão logística e random forest) e escolha o melhor pelo AUC no conjunto de teste.
Ao final, me mostre em linguagem de negócios:

2. O AUC no conjunto de teste e o que esse número significa na prática.
3. Quais variáveis mais pesam no cancelamento, em ordem de importância, e se cada uma aumenta ou reduz o risco.
4. Dois alunos fictícios, um de risco baixo e um de risco alto, com a probabilidade de churn calculada para cada um.

Etapa 3 - Levando a previsão para o app no Lovable
Até aqui, a previsão é só uma planilha. Ela só gera valor quando muda o que o aluno vê. Nas próximas três etapas, você vai evoluir o app da EnglishPro que já criou no Lovable.
Área administrativa: uma tela para importar o Excel e outra para cadastrar as campanhas.
Área do aluno: a oferta personalizada aparece logo depois do login.
Dicas para trabalhar no Lovable

4.1 Preparação: ligar o aluno do app ao aluno do Excel
O Excel identifica cada aluno pelo id_aluno. Para o app encontrar o churn certo, cada aluno cadastrado no sistema precisa ter esse mesmo número.
PROMPT 1 — Lovable — preparar o cadastro de alunos
Verifique se a tabela de alunos do sistema tem um campo que identifique o aluno pelo mesmo número usado no arquivo de previsão de churn, chamado id_aluno (número inteiro e único).
Se não tiver, crie o campo id_aluno no cadastro de alunos e atribua aos alunos importados na base de forma automatica.
4.2 Tela de importação da previsão (admin)
PROMPT 2 — Lovable — importar o Excel de churn
Na área administrativa do aplicativo, crie uma nova página chamada "Previsão de Churn", acessível apenas para administradores.
A página deve permitir o upload de um arquivo Excel (.xlsx) com duas colunas: id_aluno e probabilidade_churn (número de 0 a 100).
Regras:
1. Antes de gravar, mostre uma prévia com as 10 primeiras linhas, o total de linhas e quantas linhas têm problema (id vazio, probabilidade não numérica ou fora de 0 a 100).
2. Ao confirmar, grave no banco de dados em uma tabela churn_previsao com os campos id_aluno, probabilidade_churn e data_importacao. Se o id_aluno já existir, atualize o valor em vez de duplicar.
3. Grave em lotes de 500 linhas para suportar arquivos com mais de 10.000 linhas e mostre uma barra de progresso.
4. Ao final, mostre quantas linhas foram importadas, atualizadas e rejeitadas.
5. Na mesma página, mostre um resumo de quantos alunos há em cada faixa de churn (0–20, 20–40, 40–60, 60–80, 80–100) e uma tabela pesquisável com id_aluno, nome do aluno (quando existir no cadastro) e probabilidade, ordenada do maior para o menor risco.
Acesse a tela de importação e faça o upload do arquivo em que o e treinamento realizado anteriormente foi gerado (planiha feita pelo GPT/Claude)
4.3 Tela de campanhas de retenção (admin)
Cada campanha define para qual faixa de churn ela vale e qual desconto oferece na rematrícula antecipada. Antes de escrever o prompt, seu grupo precisa tomar uma decisão de negócio.
PROMPT 3 — Lovable — cadastro de campanhas
Na área administrativa, crie a página "Campanhas de Retenção" com cadastro, edição, listagem, ativação/desativação e exclusão de campanhas.
Cada campanha tem:
- nome da campanha;
- churn mínimo (%) e churn máximo (%), de 0 a 100;
- percentual de desconto na rematrícula antecipada;
- título da oferta e mensagem que o aluno verá (permita usar {nome} para inserir o primeiro nome do aluno);
- data de início e data de fim;
- status: ativa ou inativa.
Regra de faixa: um aluno pertence à campanha quando o churn dele é maior ou igual ao mínimo e menor que o máximo. Se o máximo for 100, o valor 100 também está incluído.
Validações: churn mínimo menor que o máximo; desconto entre 0 e 100; data de fim depois da data de início.
Regra de sobreposição: [REGRA DO GRUPO].
Na listagem, ordene as campanhas pela faixa de churn e mostre, para cada uma, quantos alunos da tabela churn_previsao caem na faixa dela.

Etapa 4. Oferta personalizada no login (aluno)
Este é o momento em que a hiperpersonalização acontece: dois alunos entram no mesmo app e cada um vê uma oferta diferente, escolhida pelos dados.
PROMPT 4 — Lovable — oferta no login do aluno
Quando um aluno fizer login na área do aluno, o sistema deve:
1. Buscar a probabilidade de churn dele na tabela churn_previsao, usando o id_aluno do cadastro.
2. Procurar a campanha ativa, dentro do período de validade, cuja faixa inclua esse valor (churn maior ou igual ao mínimo e menor que o máximo; se o máximo for 100, o valor 100 está incluído).
3. Se mais de uma campanha se aplicar, usar esta regra: [REGRA DO GRUPO].
4. Exibir um pop-up de destaque com o título da oferta, a mensagem personalizada (substituindo {nome} pelo primeiro nome do aluno), o percentual de desconto e dois botões: "Quero garantir minha rematrícula" e "Agora não".
5. Registrar em uma tabela oferta_exibida: id_aluno, campanha, data e hora da exibição e a resposta do aluno (aceitou, recusou ou sem resposta).
6. Não mostrar de novo a mesma campanha para um aluno que já respondeu.
7. Se o aluno não tiver churn importado ou se nenhuma campanha se aplicar, não mostrar nada.
Importante: o aluno nunca deve ver a probabilidade de churn dele, apenas a oferta.
